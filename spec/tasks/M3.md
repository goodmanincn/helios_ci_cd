## E3.4 YAML ↔ 图 双向转换 (4d)

### T3.4.1 YAML → Graph (1d)
**描述**: 解析 YAML 后自动布局
**步骤**:
- 复用 M2 的 DSL 解析器 (走后端 API,前端不重复)
- 节点位置:
  - 简单方案: dagre 自动布局
  - 或矩阵单独成组
- 边由 needs 自动生成

**验收**: spec/04 示例 YAML → 图布局合理无重叠

---

### T3.4.2 Graph → YAML (1.5d)
**描述**: 画布状态序列化为 YAML
**步骤**:
- 遍历节点 → stages 数组
- needs 由 edges 推导
- matrix / approval 等特殊类型分别处理
- 输出格式化的 YAML (yaml.dump 保留注释友好)
- 字段顺序稳定 (避免 diff 噪音)

**验收**: 同一个 pipeline,YAML → 图 → YAML 等价 (字段顺序可不同)

---

### T3.4.3 实时同步 (1d)
**描述**: 任一侧改动 → 另一侧自动更新
**步骤**:
- 左侧 monaco YAML 编辑器
- 右侧 React Flow 画布
- monaco 改 → debounce 500ms → 解析 → 更新画布
- 画布改 → 立即生成 YAML → 更新 monaco
- 避免循环更新 (脏标记)

**验收**: 切换"画布/YAML"tab 数据一致

---

### T3.4.4 diff 视图 (0.5d)
**描述**: 显示与上一版本的差异
**步骤**:
- 调 GET /pipelines/:id/versions 拿历史
- monaco diff editor 显示 YAML diff
- 抽屉式呈现

**验收**: 改一行,diff 准确显示

## E3.6 版本管理 (2d)

### T3.6.1 保存触发新版本 (0.5d)
**描述**: 每次保存都生成 version
**步骤**:
- PUT /api/v1/pipelines/:id/spec
- 后端: 创建 pipeline_versions 行 + 更新 current_version_id
- message 字段 (可选,用户写"为什么改")

**验收**: 改 3 次能在历史看到 v1/v2/v3

---

### T3.6.2 版本历史列表 (0.5d)
**描述**: 弹窗显示历史
**步骤**:
- GET /api/v1/pipelines/:id/versions
- 列表: version / message / 作者 / 时间
- 选中查看 diff

**验收**: 列表分页,最近在上

---

### T3.6.3 一键回滚 (0.5d)
**描述**: 任意历史版本恢复
**步骤**:
- POST /api/v1/pipelines/:id/versions/:v/restore
- 内部 = 复制旧 spec → 新建 version
- UI 二次确认

**验收**: 回滚后 current 指向新 version,内容 = 旧 spec

---

### T3.6.4 编辑冲突保护 (0.5d)
**描述**: 多人同时改提示
**步骤**:
- 保存时带 base_version_id
- 后端比对: 不一致 → 409 + 当前版本 diff
- UI 弹冲突解决窗 (强制覆盖 / 重新拉)

**验收**: 两个 tab 同时改,后保存的看到冲突

## M3 + MVP 整体验收清单

- [ ] 从零拖出一个完整流水线 (5+ 节点) 并跑通
- [ ] 改 YAML 画布实时同步,反之亦然
- [ ] 实时校验,错误高亮 < 1s
- [ ] 版本历史 + diff + 回滚可用
- [ ] 视觉 ≥ ui/pipeline-editor.html 一致度 80%
- [ ] **MVP 闭环**: 创建项目 → 拖出流水线 → push 代码 → 看实时日志 → 完成

## ★ MVP 演示脚本 (用于第 13 周结束)

1. 登录 admin
2. 新建项目 (绑 GitHub demo 仓库)
3. 拖出一条流水线: checkout → 测试 → 构建 → 审批 → 部署 (跳过实际部署,日志输出 "deploy ok")
4. 切到 YAML tab 看代码
5. 保存并启用
6. 在 GitHub push 一次代码
7. UI 实时看 run 滚动到审批节点暂停
8. 审批通过
9. run 完成 ✅

## 风险与降级方案

- **react flow 学习曲线** — 留 2d 缓冲学习
- **双向转换 bug 多发区** — 用 property-based testing (fast-check)
- **YAML 反解布局丑** — dagre 默认布局够用,接受不完美
- **若进度落后,降级**:
  - 砍掉 E3.6 版本管理 (-2d)
  - 拖拽改为"点击插入"(-1d)
  - 只保留 YAML 编辑模式 + 校验,把"可视化"推到 v1.1
