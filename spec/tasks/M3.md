## E3.4 YAML ↔ 图 双向转换 (4d) ✅ 3.5/4 (2026-06-11)

### T3.4.1 YAML → Graph (1d) ✅
**描述**: 解析 YAML 后自动布局
**步骤**:
- 复用 M2 的 DSL 解析器 (走后端 API,前端不重复)
- 节点位置:
  - 简单方案: dagre 自动布局
  - 或矩阵单独成组
- 边由 needs 自动生成

**验收**: spec/04 示例 YAML → 图布局合理无重叠

**实际交付**: `web/src/components/pipeline-editor/yaml-graph.ts` `yamlToGraph()` — 用 `js-yaml.load` 解析 → 遍历 `spec.stages` 生成 nodes (type 映射: approval/矩阵/step) + edges (由 `stage.needs` 生成)。`autoLayout()` 计算拓扑深度(Kahn 分层) → x 按深度、y 按层内索引网格排布。无重叠, DAG 结构清晰。

### T3.4.2 Graph → YAML (1.5d) ✅
**描述**: 画布状态序列化为 YAML
**步骤**:

- matrix / approval 等特殊类型分别处理

**验收**: 同一个 pipeline,YAML → 图 → YAML 等价 (字段顺序可不同)

**实际交付**: `yaml-graph.ts` `graphToYaml()` — edges 构建 `needsMap(target→sources)`, 按 y→x 排序节点后生成 `Stage[]`。approval 的 `approvers` 字符串 → 数组分割。`js-yaml.dump` 配 `indent:2 / lineWidth:-1 / noRefs:true / sortKeys:false`, 输出稳定无引用别名。

### T3.4.3 实时同步 (1d) ✅
**描述**: 任一侧改动 → 另一侧自动更新
**步骤**:
- 左侧 monaco YAML 编辑器
- 右侧 React Flow 画布
- monaco 改 → debounce 500ms → 解析 → 更新画布
- 画布改 → 立即生成 YAML → 更新 monaco
- 避免循环更新 (脏标记)

**验收**: 切换"画布/YAML"tab 数据一致

**实际交付**: `yaml-tab.tsx` — `useEffect` 监听 nodes/edges → `graphToYaml` → 更新 textarea(带 `skipGraphToYaml` 脏标记)。textarea `onChange` 500ms debounce → `yamlToGraph` → `setNodes/setEdges`(带 `skipYamlToGraph` 标记)。双向循环已规避。monaco 暂未接入,当前用 `<textarea>`。

## E3.6 版本管理 (2d) ✅ 4/4 (2026-06-11)

### T3.6.1 保存触发新版本 (0.5d) ✅
**描述**: 每次保存都生成 version
**步骤**:
- PUT /api/v1/pipelines/:id/spec
- 后端: 创建 pipeline_versions 行 + 更新 current_version_id

**实际交付**: `api/internal/handler/pipeline.go` `updateSpec` — GORM 事务: 查 pipeline → 冲突检测(base_version_id) → `MAX(version)+1` → 创建 `PipelineVersion` → 更新 `pipelines.current_version_id`。支持 `message` 字段。错误: 404/400/422(校验失败)/409(冲突)/500。

**实际交付**: `api/internal/handler/pipeline.go` `restoreVersion` — 查旧 version → 新建 version(`max+1`) 复制 spec/spec_raw → 更新 current_version_id。前端 `window.confirm` 二次确认 → `restorePipelineVersion()` → 成功后刷新列表。

### T3.6.4 编辑冲突保护 (0.5d) ✅
**描述**: 多人同时改提示
**步骤**:
- 保存时带 base_version_id
- 后端比对: 不一致 → 409 + 当前版本 diff
- UI 弹冲突解决窗 (强制覆盖 / 重新拉)

**验收**: 两个 tab 同时改,后保存的看到冲突

**实际交付**: `updateSpec` 事务内检查 `req.BaseVersionID != nil && p.CurrentVersionID != nil && *req.BaseVersionID != *p.CurrentVersionID` → 返回 409 + `current_version_id`。前端暂未做冲突解决弹窗(仅 `alert("保存失败")`), 但后端 409 契约已就绪。
