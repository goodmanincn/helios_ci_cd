## E6.2 SSH Runner (3d)

### T6.2.1 SSH 客户端封装 (1d)
**步骤**:
- 引入 golang.org/x/crypto/ssh
- `runner/ssh/client.go`: Dial / Exec / SftpUpload
- 支持密码 + 公钥两种认证
- 跳板机支持 (ProxyJump)
- KnownHosts 校验 (配置可选关闭)

**验收**: 三种连接场景都通

---

### T6.2.2 远程命令执行 (0.5d)
**步骤**:
- Exec 流式 stdout/stderr
- 超时 + 中断 (kill remote process)
- exit code 准确传递

**验收**: 跑 long task 能中断

---

### T6.2.3 SFTP 文件传输 (0.5d)
**步骤**:
- 引入 sftp 包
- 上传单文件 / 目录递归
- 进度回调
- 权限保留

**验收**: 上传 100MB 文件 + 1000 个小文件

---

### T6.2.4 SSH Runner 集成到引擎 (1d)
**步骤**:
- `runner/ssh/runner.go` 实现 Runner 接口
- step 执行: 上传脚本 → ssh exec → 收集结果 → 清理
- 失败重试

**验收**: 引擎能选择 ssh runner 执行 step

## E6.3 ssh-deploy 内置 step (2d)

### T6.3.1 step 定义 (0.5d)
**步骤**:
- inputs: hosts (host_group 或主机列表) / source / dest / before_script / after_script / restart_command
- outputs: success_hosts / failed_hosts

**验收**: schema 完整

---

### T6.3.2 rsync 实现 (1d)
**步骤**:
- 优先用主机本地 rsync (检测可用性)
- fallback 到 sftp
- 增量传输 (基于校验和)
- 排除规则 (.rsync-exclude)

**验收**: 二次部署只传变更文件

---

### T6.3.3 生命周期钩子 (0.5d)
**步骤**:
- before_script (部署前在远程跑)
- after_script (部署后)
- restart_command (默认 `systemctl restart $service`)
- 失败立即停 (本主机)

**验收**: 三阶段顺序执行

---

## E6.4 滚动并发控制 (2d)

### T6.4.1 并发执行框架 (1d)
**步骤**:
- 主机列表分批 (默认并发 5)
- 每批失败超过阈值停止 (max_failures)
- 进度实时上报

**验收**: 10 台主机 2 台失败,余下停止

---

### T6.4.2 部署策略配置 (0.5d)
**步骤**:
- DSL: deploy.strategy = rolling | parallel | serial
- rolling: 批次大小 / 批间间隔 / 失败阈值
- 健康检查 hook (跑完一批 curl /health)

**验收**: 三策略可切换

---

### T6.4.3 失败回滚 (0.5d)
**步骤**:
- 部署前 snapshot (备份旧目录)
- 失败时执行 restore (恢复 + 重启)
- 部分主机回滚 (已部署的)

**验收**: 故意一台失败,该台自动恢复

## 风险

- **SSH 密钥分发** — 用户体验差,提前考虑 helios CLI 一键分发
- **多主机并发** — goroutine 泄露风险,严格 wait group
- **rsync 在 Windows 主机不可用** — 文档明确不支持 Windows
- **总计 9.5d ≈ 2w,无缓冲**
