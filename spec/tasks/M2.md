### T2.2.3 调度器主循环 (1d)  ✅ (纯逻辑层)
**描述**: 按 DAG 顺序调度执行
**步骤**:
- `engine/scheduler.go`:
  - 维护 ready queue (依赖已满足)
  - 提交 stage 到 worker pool (Asynq)
  - 监听 stage 完成事件 → 推进下游
  - 失败传播 (除非有 if: always() / failure())
- 并发数可配置

**验收**: 5 stage 含并行 + 串行 + 矩阵,执行顺序符合 DAG

**实际交付 (纯逻辑层)**: `api/pkg/engine/scheduler.go`
- 设计取舍: 本文件只做"状态机", 不直接调 asynq/不写 DB; 由 caller (worker 端 scheduler 进程) 包一层做 IO. 这样纯函数化, 单测覆盖全面, IO 故障在 IO 层定位.
- `Scheduler` 维护 NodeStatus map (pending/ready/running/success/failed/skipped/canceled), 提供:
  - `NextReady() []NodeID`: 拿当前可派发节点, 内部置 running 防重复派发
  - `Complete(id, result)`: 报告完成, 仅 success/failed/canceled 三种结果合法
  - `CancelAll()`: 整个 run 取消
  - `Done() / Outcome()`: 终态判断 + 整体结果汇总
- 失败传播: 默认上游 failed/canceled/skipped → 下游 skip; `if: always()` 强制运行; `if: failure()` 仅故障时跑 (无故障也 skip)
- 12 个测试覆盖: 线性 success / fan-out 并行 / failed 传播 skip / if always 后救场 / if failure 仅故障跑 / CancelAll / Complete 拒绝终态/无效/未知节点 / 端到端 5stage + matrix
- **IO 接入留后续 task**: worker 端要写一个 RunStageWorker 拉 `helios:stage:execute` 任务, 写 stage 状态进 DB, 报回给 Scheduler; 这块需要先建 stages 表 schema 跟 M1 的 stages 模型对齐, 留作 T2.2.4 增量. 当前 M1 的 single-stage `helios:build` 走法继续可用, 不阻塞 E2.3/E2.4/E2.5/E2.6.

- 真接入 LogsPanel 留 worker stage executor 把 ExecContext.Log 包成 masker.Writer 即可生效
