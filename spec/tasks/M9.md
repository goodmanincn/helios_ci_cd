## E9.1 action.yml 契约 + 容器化执行器 (5d)

### T9.1.1 action.yml 规范 (1d)
**步骤**:
- `pkg/plugin/spec.go` 完整 schema
- 字段: name / description / inputs / outputs / runs (container/composite/javascript)
- 校验 + 文档示例
- container 子: image / args / env / entrypoint
- composite 子: steps (复合 step)

**验收**: 10 个示例 action.yml 都能 parse 通过

---

### T9.1.2 inputs/outputs 接口 (1d)
**步骤**:
- inputs 通过环境变量传 (INPUT_XXX)
- outputs 通过 stdout 协议 (`::set-output name=X::value`)
- 文件系统约定 (workspace / artifacts / runner-tmp)
- 兼容 GitHub Actions 大部分协议

**验收**: 一个 echo 插件能输出值给下游

---

### T9.1.3 容器化执行器 (1.5d)
**步骤**:
- 复用 Docker runner (M1)
- 镜像拉取策略 (always/IfNotPresent/Never)
- 镜像签名验证 (cosign,可选)
- 资源限制 (cpu/mem 默认值)
- 安全沙箱 (no-new-privileges, 只读 rootfs 可选)

**验收**: 跑 trivy 插件能扫镜像

---

### T9.1.4 composite step 支持 (1d)
**步骤**:
- 解析 composite 中的 sub-steps
- 子 step 复用引擎递归执行
- 嵌套 secrets / vars 传递
- 防无限递归 (深度限制 5)

**验收**: 一个 composite 插件 (含 3 个 sub-step) 工作

---

### T9.1.5 插件级 secrets / permissions (0.5d)
**步骤**:
- action.yml 声明 needs_secrets
- action.yml 声明 needs_permissions (network/fs/exec)
- 执行时强制
- 用户安装时显示权限请求

**验收**: 越权调用被拦截

### T9.2.4 引用解析 (uses: ...) (1d)

## 风险

- **action.yml 协议设计变更成本高** — 上线前 review 慎重,留 escape hatch
- **GitHub Actions 兼容性** — 不追求 100%,只做声明式部分,Composite/JS Action 后置
- **官方插件维护成本** — 接受社区贡献,官方只保 10 个核心
- **registry 高可用** — CDN + 多镜像源
- **总计 20d ≈ 4w,无缓冲**
